## 결과

### 1. 배경 제거 품질 — **신 경로 승**

| | 배경 판정 | 비고 |
|---|---|---|
| 구 경로 | `flat #ffffff` | 크로마 배경이 **아니다**. 로그: `transparent=false (inherited from reference bg)`, `isGreenDominant: green=0/65536` → 후처리가 키를 못 찾아 제거 자체를 시도하지 않음 |
| 신 경로 | `flat #02fafd` 테두리 100% | 크로마 키 자동 선택(**cyan**)이 그대로 반영됨 |

크로마 키 자동 선택이 실전에서 옳게 동작했다. base 의 망토가 **크림슨**이라 마젠타는
인접(둘 다 R 이 높다)이고, 정본 분기표가 이 경우 그린을 권한다. 우리 선택기는 base 의
마젠타 배경을 소재 표본에서 제외한 뒤 남은 소재색과 가장 먼 **cyan** 을 골랐다.

### 2. 프레임 분할·정렬 — **혼합. 신 경로가 크기·바닥선에서 우세, 셀 경계 침범은 열세**

| 지표 | 구 경로 | 신 경로 |
|---|---|---|
| 피사체 높이 편차 σ | 19.6px | **3.6px** |
| 바닥선 편차 σ | 3.9px | **1.5px** |
| 중심 x 편차 σ | **1.2px** | 22.1px |
| 셀 경계 침범 | 없음 | **4/4 프레임 전부** |

크기 일관성은 신 경로가 5.4배 안정적이다. 그런데 **셀 경계 침범이 4프레임 전부에서
났다** — bbox 폭이 셀 폭(443px)과 같은 프레임이 2개다.

원인: 프롬프트에 넣은 safe margin 은 **요청 셀(256px)의 24px** 인데 실제 셀은 443px 이다.
비율로 치면 5.4% 라 정본의 9.4% 에 못 미치고, 애초에 모델이 받은 수치가 실제 캔버스와
무관하다. 셀 기하를 출력에서 유도하도록 고쳤지만 **프롬프트의 margin 수치는 여전히 요청
셀 기준**이다.

구 경로가 침범이 없는 것은 셀이 512px 로 넓어서일 뿐, 정렬을 더 잘해서가 아니다.

### 3. 프레임 간 일관성 — **신 경로 승. 단 이번 실행만으로 체인의 핵심 이점을 증명하지 못한다**

이번 구 경로 실행도 정체성은 잘 유지했다 — base 를 ref 로 직접 붙였으니 당연하다.
**앵커 체인의 주장은 "행이 여러 개일 때 드리프트가 누적되지 않는다"는 것이고, 행 하나짜리
비교로는 검증되지 않는다.** 다중 방향·다중 상태 런이 필요하다.

대신 이번 작업에서 **인과가 우연히 실증됐다.** 첫 실행에서 셀 기하 추정 버그로 앵커가
배경 조각(셀 좌상단 256×256 = 시안 + 귀 끝)으로 구워졌고, 그 앵커로 만든 액션 행은
지팡이가 사라지고 얼굴·후드·의상이 통째로 바뀌었다. 기하를 고쳐 앵커가 온전한 단일 포즈로
나오자 같은 프롬프트에서 지팡이·붉은 보석·금색 장식·꼬리·부츠가 전부 보존됐다.

> **나쁜 앵커 → 전면 드리프트, 좋은 앵커 → 정체성 유지.** 앵커가 무엇을 하는지에 대한
> 직접 증거다.

### 4. 애니메이션 질 — **판정 보류**

| | 인접 프레임 평균 절대차 |
|---|---|
| 구 경로 | 29.4, 21.5, 28.2 |
| 신 경로 | 38.2, 39.4, 46.3 |

숫자만 보면 신 경로의 변화량이 크지만 **이 지표로 우열을 말할 수 없다.** 구 경로는 배경이
흰색이라 차분이 희석되고, 신 경로는 캐릭터가 셀을 꽉 채워 같은 이동에도 차분이 커진다.

육안으로는:
- 구 경로 — idle 을 요청했는데 프레임 2·3 이 다리를 벌리고 지팡이를 대각선으로 든 **무관한
  포즈**다. 루프가 되지 않는다.
- 신 경로 — 호흡 수준의 미세 변화. idle 로는 적절하지만 변화가 작아 애니메이션으로 읽히는지
  의문이 남는다.

**로코모션(walk/run)으로는 아직 비교하지 않았다.** 정본이 그 상태들을 experimental 로
분류하고 *"the most reliable path is candidate generation plus human frame picking"* 이라고
적으므로, 자동 비교보다 사람이 프레임을 고르는 경로(④b)가 답일 가능성이 높다.

> **정정 (2026-08-16, 원본 대조 후)**: 아래 "결함 1" 은 결함이 아니라 **그리드 슬라이싱의
> 증상**이다. 정본은 프롬프트 px 를 그대로 두고 추출을 components 로 하며, 이웃 접촉은

## 이번 실행이 드러낸 결함 3건

1. ~~**safe margin 이 실제 셀과 무관하다**~~ → **그리드 슬라이싱의 증상.** 프롬프트가 요청
   셀(256) 기준 24px 을 말하고 실제 셀은 443px 이지만, 정본도 px 로만 말한다. 셀 경계 침범은
   추출이 components 가 되면 사라진다.
2. **codex 는 가이드의 픽셀 치수를 따르지 않는다** — 1024×256(4:1) 요청 → 1774×887(2:1).
   `image_gen` 이 고정 종횡비만 내므로 4:1 스트립은 불가능하다. 따르는 것은 **프레임 개수와
   배열**뿐이다. (고침: 셀 기하를 출력에서 유도)
3. **콘텐츠 크롭이 raw 생성물에서 무의미하다** — 알파가 없어 bbox 가 셀 전체가 된다.
   `sourceHasAlpha` 로 드러내고 있으나, 추출 단계가 붙기 전까지 앵커는 크로마 배경을 달고
   레퍼런스로 나간다.

| 지표 | 구 경로 (2×2 그리드) | ④a 신 경로 (그리드 슬라이싱) | ⑤ 신 경로 (컴포넌트 추출) |

**"셀 경계 침범"은 추출이 붙자 완전히 사라졌다.** 정본 진단이 정확했다 — 그건 결함이
아니라 그리드 슬라이싱의 증상이었고, 프롬프트로 고칠 것이 아니었다.

바닥선 σ 가 정확히 0.0px 인 것은 `fit_to_cell` 의 `align_y: bottom` 이 모든 프레임의
최하단 픽셀을 `cellH - safeMarginY` 에 앉히기 때문이다. 높이 σ 0.0px 은 네 프레임이 모두
safe 영역 높이(208px)에 맞춰 스케일된 결과다.

### 인접 프레임 차가 줄어든 것은 개선이다

30.6 → 6.3 은 모션이 줄어든 게 아니라 **위치 지터가 제거된 것**이다. raw 에서는 프레임마다
캐릭터 위치가 달라 그 이동이 차분에 섞였다. 추출 후 남은 4~6 이 실제 포즈 변화량이고,
idle 호흡으로는 작은 값이다 — 애니메이션으로 읽히는지는 ⑥의 모션 QA 에서 판정한다.
